# Releasing PC Power

Steps only the owner can do (they need your identity, your accounts or a password only you should know), in the order to do them.

## 1. Android upload key (do this once, keep it forever)

Google Play identifies your app updates by this key. Lose it and you need Google support to reset it, so back it up.

1. Install Android Studio (it includes `keytool`), or any Java JDK.
2. Open a terminal in `android-app\android` and run:

       keytool -genkey -v -keystore upload-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

   Choose a strong password and answer the questions (your name, Cape Town, ZA).
3. Create `android-app\android\key.properties` with:

       storeFile=../upload-key.jks
       storePassword=YOUR PASSWORD
       keyAlias=upload
       keyPassword=YOUR PASSWORD

   (`storeFile` is relative to `android-app\android\app`, so `../upload-key.jks` means the file sits in `android-app\android`.)
4. Back up `upload-key.jks` and the password somewhere safe that is not this repository (a password manager, plus a USB stick).
   Both files are already ignored by git. Never commit them, never paste the password into a chat.
5. Build the file Google Play wants:

       cd android-app
       flutter build appbundle --release

   The result is `build\app\outputs\bundle\release\app-release.aab`.

## 2. Google Play

1. Create a developer account at https://play.google.com/console as a **personal** account. It costs USD 25 once and needs your ID.
2. Create the app: name "PC Power", free, app (not game).
3. When asked, turn on **Play App Signing** (Google keeps the final signing key; your upload key from step 1 only proves updates come from you).
4. Store listing: short and full description, the icon (`windows-app/ui/icon-512.png`), at least 2 phone screenshots, and a 1024x500 feature graphic.
5. Privacy policy URL: the hosted Privacy Policy (see step 4).
6. Data safety form. Honest answers for this app:
   - Data collected: none sent to you or any server. The app talks only to your own PCs.
   - Data shared: none.
   - Encryption in transit: yes (TLS to the PC).
   - Users can delete data: yes (uninstalling removes everything; unpairing removes the phone from the PC).
7. Content rating questionnaire: a utility with no user-generated content and no ads.
8. **Closed test:** new personal accounts must run a closed test with at least 12 testers who stay opted in for 14 days in a row before you can apply for production. Upload the `.aab` to a closed testing track, add 15 to 20 testers (friends, colleagues) by email so a few dropouts do not reset the clock, and ask them to install it and open it a few times.
9. After 14 days, apply for production access, then publish.

## 3. Windows: signing, so Windows stops warning people

Without a signature, Windows SmartScreen shows "Windows protected your PC" on first run.

- **Microsoft Store (recommended).** Registration is free for individual developers and the Store signs and hosts the app for free.
  Start at https://learn.microsoft.com/windows/apps/publish/get-started and choose Individual developer (personal Microsoft account, ID and selfie check).
  Then tell Claude: the app has to be packaged as MSIX, and the background service part needs Microsoft's approval
  for a "packaged service", so that is the one uncertain step.
- **Buy a code-signing certificate.** An OV code-signing certificate from a certificate authority, issued to your name after an ID check.
  It comes on a hardware token or a cloud signing service, and costs money every year. Then each release is signed with `signtool`.
- Microsoft's own Azure signing service is not an option for now: it only accepts individual developers from the USA and Canada.

## 4. Host the legal documents

The Play listing needs a public Privacy Policy link. The documents are generated by `tools/legal.py` into `docs/legal/`.
They can be hosted on muneermiller.github.io (see `pc-power/` there) or with GitHub Pages on this repository.

## 5. Before each release

1. Bump the version in `windows-app/install_windows.go` (`appVersion`), `windows-app/winres/winres.json` and `android-app/pubspec.yaml`.
2. Run `python3 tools/icon.py` if the icon changed, then `go-winres make --arch amd64` in `windows-app`.
3. Push: GitHub Actions runs the Windows install test. Only release if it passes.
4. Test on a real PC and phone: pair, shut down, turn on, a schedule, the widget.

## 6. iPhone (later)

Needs a Mac (or a cloud Mac), Xcode and an Apple Developer account (USD 99 a year). The phone app is Flutter, so most of it carries over;
the widget, the quick tile and the local-network permission need iPhone-specific work.
